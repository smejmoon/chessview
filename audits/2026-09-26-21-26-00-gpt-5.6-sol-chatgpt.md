## Findings

### The fail-closed presentation contract is tested only against a stub renderer

**Evidence:** `docs/components/interface.md` §Composition direction and §Verification require a normal presentation failure to produce a degraded/unavailable surface without rewriting valid structural state. `src/nodus-presenter.js` correctly catches `renderer.render()` failure and delegates to `renderer.renderFailure()`, while `src/nodus-renderer.js` contains the actual degraded DOM, `Unavailable` status, Back control, and Retry control. `test/nodus-presenter.test.js` verifies only that a supplied stub `renderFailure()` is called; the complete `test/` surface contains no `nodus-renderer` test, so no automated assertion would fail if the production `renderFailure()` became empty, lost its degraded status, or stopped wiring Retry/Back.

**Why it matters:** The refactor deliberately moved presentation failure out of controller state and into the presenter/renderer boundary. That makes the renderer's degraded fallback the only concrete enforcement of the user-visible fail-closed behavior. The current tests pin delegation but not the production fallback that fulfills the contract, leaving the key behavior vulnerable to a silent regression.

**Suggested next action:** Add a deterministic renderer-level test using a minimal DOM harness that invokes the real `renderFailure()` and asserts the unavailable status plus Retry/Back wiring; keep the existing presenter test for the separate delegation and structural-truth invariant.

**Confidence:** high
