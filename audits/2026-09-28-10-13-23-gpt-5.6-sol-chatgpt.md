## Findings

### Ordering test does not deterministically observe the node before the edge write

**Evidence:** `test/move-materialization.test.js`, test `target position exists before the durable move edge is written`. The patched `IDBObjectStore.prototype.put` starts a separate asynchronous `nodes.get(resolved.target)` when the edge `put` is invoked, assigns `observedTarget` only in that request's `onsuccess`, then immediately lets the edge write continue. The test awaits `materializeMove()`, not that read request. Its final assertion therefore depends on the independent read callback having fired before materialization's edge transaction completes and the test resumes. The synchronized backlog explicitly leaves deterministic ordering-test verification open.

**Why it matters:** the test is intended to prove the new durability ordering, but its pass/fail can depend on fake IndexedDB scheduling rather than solely on the implementation contract. A scheduling change can make correct code fail, and the test is not the requested deterministic fault-injection proof that failed target establishment prevents edge persistence.

**Suggested next action:** replace this timing probe with deterministic fault injection at a controllable dependency boundary. Force target establishment to reject and assert that no outgoing edge exists afterward; separately keep the successful materialization/evidence-preservation assertions. If an explicit call-order assertion remains useful, inject collaborators rather than racing IndexedDB callbacks.

**Confidence:** high

### The implementation has not yet supplied the required failure-path proof

**Evidence:** `backlog/2026-09-27-move-materialization-durability.md` §Complete requires deterministic fault injection showing failed target establishment leaves no durable edge. The changed `test/move-materialization.test.js` adds only a successful-path ordering observation; it never causes `PositionRepository.ensure()` to fail. `src/move-materialization.js` does now await `positionRepository.ensure(resolved.target)` before `putManualEdge(edge)`, so the implementation shape supports the invariant, but the required failure branch is untested.

**Why it matters:** the original defect is specifically a partial-persistence failure mode. Successful-path coverage cannot establish that a rejected target write prevents edge creation, so the change is not yet verified against the backlog's completion condition.

**Suggested next action:** add deterministic injection of a rejecting target-establishment operation and assert both rejection and absence of the corresponding durable edge. Then run the deterministic test/build suite before considering the backlog complete.

**Confidence:** high
